# КТ#5. Продвинутые фичи

**Максимум: 10 баллов**

Выбрать из направлений и либо интегрировать его в проект из КТ №4, либо создать новый

## Требования и критерии

### Направление A — Realtime чат на Socket.io (5 баллов)

Добавить в проект WebSocket-чат с аутентификацией.

- `Socket.io` подключён к существующему `Express`-серверу;
- при подключении проверяется JWT-токен через `middleware` (1 балл);
- реализован базовый функционал и события `message:send`, `message:new`, `user:online`, `user:offline` (1 балл);
- при подключении новый пользователь получает список онлайн-пользователей, при отключении остальные получают уведомление (1 балл).
- реализованы комнаты и события `room:join`, `room:leave`, `room:message` (2 балла);

### Направление B — Фоновые задачи на BullMQ (5 баллов)

Добавить в проект очередь задач с мониторингом.

- `Redis` запущен через `Docker`;
- созданы очереди `transactional-email` и `marketing-email` с воркерами;
- при регистрации пользователя в очередь `transactional-email` добавляется задача `email-credentials`, воркер отправляет письмо с именем, email и паролем пользователя (2 балла);
- реализована задача с задержкой: через минуту после регистрации в очередь `marketing-email` добавляется задача `welcome-email`, отправляется маркетинговое письмо с информацией о нашем продукте (2 балла);
- `BullBoard` доступен по `/admin/queues` и показывает состояние очередей (1 балл);

### Направление C — OpenAPI (5 баллов)

Любым из способов (изученных либо найденных самостоятельно) добавить к проекту `OpenAPI`-спецификацию и `Swagger UI` / `Scalar`.

Должны быть описаны и работать через интерфейс:
- схемы входных данных (и, хотя бы на двух эндпоинтах, примеры);
- схемы выходных данных (и, хотя бы на двух эндпоинтах, примеры);
- возможные коды ответа;
- теги, саммари и хотя бы два дескрипшена;
- требования к аутентификации на конечных точках и возможность авторизоваться через интерфейс.

- `GET /api/products`
- `GET /api/products/:id`
- `POST /api/products`
- `PATCH /api/products/:id`

- `POST /api/auth/register`
- `POST /api/auth/login`
- `POST /api/auth/refresh`
- `POST /api/auth/logout`

- `GET /api/users`
- `GET /api/users/me`
- `POST /api/users/:id/profile`

Как альтернатива - можно переписать проект на `oRPC`.
